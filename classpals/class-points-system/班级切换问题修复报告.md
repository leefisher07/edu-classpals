# 班级切换问题修复报告

**修复日期**: 2026-03-23
**问题**: 切换班级后，班级选择器没有更新，班级管理模块没有数据
**修复状态**: ✅ 已完成

---

## 问题描述

用户在班级管理页面点击"切换到此班级"或在顶部下拉菜单切换班级后：
1. ❌ 顶部班级选择器显示的班级名称没有更新
2. ❌ 班级管理页面的班级卡片没有更新激活状态
3. ❌ 其他页面（如学生管理）仍然显示旧班级的数据

---

## 根本原因分析

### 原因1：切换班级时没有调用后端API

**问题代码** (`frontend/app/dashboard/layout.tsx` 第72-74行):
```tsx
const handleClassSwitch = (cls: any) => {
  updateUser({ currentClassId: cls.id })
}
```

**问题**：
- 只更新了前端本地状态
- 没有调用后端的 `/classes/:id/activate` API
- 后端数据库中的 `user.currentClassId` 没有更新
- 其他页面查询数据时仍然使用旧的班级ID

### 原因2：数据结构解析错误

**问题代码** (`frontend/app/dashboard/layout.tsx` 第69行):
```tsx
const classes: any[] = (classesData as any)?.data?.classes || []
```

**实际数据结构**：
```json
{
  "code": 200,
  "message": "success",
  "data": [
    { "id": "xxx", "name": "测试班级1", "isActive": true, ... },
    { "id": "yyy", "name": "测试班级2", "isActive": false, ... }
  ],
  "timestamp": "2026-03-23T..."
}
```

**问题**：
- 代码期望 `data.classes`，但实际上 `data` 就是数组
- 导致 `classes` 变量为空数组
- 班级选择器无法显示班级列表

### 原因3：当前班级判断逻辑不准确

**问题代码** (`frontend/app/dashboard/layout.tsx` 第70行):
```tsx
const currentClass = classes.find((c: any) => c.id === user?.currentClassId) || classes[0]
```

**问题**：
- 只依赖前端状态 `user.currentClassId`
- 没有使用后端返回的 `isActive` 字段
- 当后端和前端状态不一致时，显示错误的班级

---

## 修复方案

### 修复1：调用后端激活API

```tsx
const handleClassSwitch = async (cls: any) => {
  try {
    await classesApi.activate(cls.id)
    updateUser({ currentClassId: cls.id })
    // 刷新班级列表以更新 isActive 状态
    await refetchClasses()
  } catch (error) {
    console.error('Switch class error:', error)
  }
}
```

**改进点**：
- ✅ 调用后端API更新数据库
- ✅ 更新前端状态
- ✅ 刷新班级列表获取最新的 `isActive` 状态
- ✅ 添加错误处理

### 修复2：修正数据结构解析

```tsx
const { data: classesData, refetch: refetchClasses } = useQuery({
  queryKey: ['classes'],
  queryFn: () => classesApi.list(),
  enabled: isAuthenticated,
})

const classes: any[] = (classesData as any)?.data || []
```

**改进点**：
- ✅ 直接使用 `data` 而不是 `data.classes`
- ✅ 添加 `refetch` 函数用于手动刷新数据

### 修复3：优化当前班级判断逻辑

```tsx
const currentClass = classes.find((c: any) => c.isActive) ||
                     classes.find((c: any) => c.id === user?.currentClassId) ||
                     classes[0]
```

**改进点**：
- ✅ 优先使用后端返回的 `isActive` 字段
- ✅ 其次使用前端状态 `currentClassId`
- ✅ 最后降级到第一个班级

```tsx
const { data: classesData, refetch: refetchClasses } = useQuery({

const classes: any[] = (classesData as any)?.data || []
const currentClass = classes.find((c: any) => c.isActive) ||
                     classes.find((c: any) => c.id === user?.currentClassId) ||

const handleClassSwitch = async (cls: any) => {

    // 刷新班级列表以更新 isActive 状态

  }
}
```

## 技术细节

### 后端API

**激活班级API**:
- **端点**: `POST /api/classes/:id/activate`
- **功能**: 更新 `user.currentClassId` 为指定班级ID
- **返回**: `{ id: string, isActive: true }`

**获取班级列表API**:
- **端点**: `GET /api/classes`
- **功能**: 返回当前用户的所有班级，包含 `isActive` 字段
- **返回**:
```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "id": "xxx",
      "name": "测试班级1",
      "teacherName": "张老师",
      "studentCount": 5,
      "totalPoints": 10,
      "isActive": true,
      "createdAt": "...",
      "updatedAt": "..."
    }
  ]
}
```

### 数据流程

1. **用户点击切换班级**
   ```
   用户操作 → handleClassSwitch()
   ```

2. **调用后端API**
   ```
   classesApi.activate(classId) → POST /api/classes/:id/activate
   ```

3. **后端更新数据库**
   ```
   UPDATE users SET currentClassId = :classId WHERE id = :userId
   ```

4. **更新前端状态**
   ```
   updateUser({ currentClassId: classId })
   ```

5. **刷新班级列表**
   ```
   refetchClasses() → GET /api/classes → 更新 isActive 字段
   ```

6. **UI自动更新**
   ```
   React Query 自动触发重新渲染 → 显示新的班级名称和激活状态
   ```
